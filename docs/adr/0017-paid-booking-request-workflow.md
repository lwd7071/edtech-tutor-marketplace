# ADR 0017: Student requests, Teacher confirms paid bookings

**Status: Accepted — 2026-10-29.** Student starts a paid lesson by requesting a preferred time from an active purchased package. A request does not reserve a session; the Teacher accepts with the final start time, delivery mode, and required logistics, which creates the paid Booking and reserves one session in the same transaction. A Teacher may reject with a reason, and the Student may cancel while the request remains pending. Each package may have at most one pending request. The purchased session duration is snapshotted on StudentPackage so later catalog changes cannot alter the booking length. This keeps the paid flow distinct from the existing trial-request flow and avoids presenting a Student request as a confirmed calendar slot.
